# EkalSahayak (Lakshya AI) — Multilingual Architecture & Localization Guide (i18n)

## Overview
EkalSahayak provides production-grade multilingual support across **30 languages** (including conversational Roman-script Hinglish `hi-Latn`), allowing learners across rural Odisha and India to learn Science in their primary language.

Switching the app language switches **every visible string** instantly without page reload, updates RTL layout mirroring where appropriate (`dir="rtl"`), and persists across sessions, offline storage (IndexedDB), and cloud profile sync (`PATCH /api/auth/me/preferences`).

## Fallback Chains

When a translation key or curriculum explanation is unavailable in a requested locale, the system walks down the predefined fallback chain until a verified translation is found. Raw keys (such as `settings.title`) are never exposed to the learner.

| Locale Code | Language | Fallback Chain |
|---|---|---|
| `kxu` | Kui | `or` → `hi` → `en` |
| `tcy` | Tulu | `kn` → `en` |
| `bho`, `mai`, `mag` | Bhojpuri, Maithili, Magahi | `hi` → `en` |
| `raj`, `hne` | Rajasthani, Chhattisgarhi | `hi` → `en` |
| `sa` | Sanskrit | `hi` → `en` |
| `kok` | Konkani | `mr` → `en` |
| `doi` | Dogri | `hi` → `en` |
| `brx` | Bodo | `as` → `en` |
| `mni` | Manipuri | `bn` → `en` |
| `hi-Latn` | Hinglish | `hi` → `en` |
| Others | Tier A / B | `en` |

## How to Add a New Language

1. **Register the Locale Code**:
   Add the BCP-47 code to `SupportedLanguage` in `agent/app/models/auth.py` and `SUPPORTED_LANGUAGE_CODES` in `frontend/artifacts/lakshya-ai/src/i18n/languages.ts`.
2. **Define Metadata**:
   In `frontend/artifacts/lakshya-ai/src/i18n/languages.ts`, add the language entry with native name, English name, script sample, tier, text direction (`'ltr'` or `'rtl'`), and font family.
3. **Generate Locale File**:
   Run `pnpm i18n:translate` to generate `src/i18n/locales/<code>.json` from fallback chains.
4. **Verify Quality**:
   Run `pnpm i18n:check` to ensure 100% key parity with `en.json`.

## How to Mark a Translation as Human-Reviewed

When human linguists or teachers review a locale file:
1. Open `src/i18n/locales/<code>.json`.
2. Update the `_meta` block:
   ```json
   {
     "_meta": {
       "locale": "or",
       "name": "ଓଡ଼ିଆ",
       "mt": false
     }
   }
   ```
3. Setting `"mt": false` removes the "Beta" tag in the Settings language picker for that locale.

## Numerals & Font Typography

- **Numerals Toggle**:
  Students can switch between Western Arabic digits (`0-9`) and regional Indic digits (e.g. `୧୨୩` in Odia, `१२३` in Devanagari). Formatting is performed by `formatNumber` and `formatPercent` in `src/lib/formatters.ts`.
- **Typography**:
  Dynamic `--font-ui` CSS variable automatically maps the active script to subsetted Noto Sans web fonts (`Noto Sans Oriya`, `Noto Sans Devanagari`, `Noto Sans Bengali`, `Noto Sans Tamil`, `Noto Nastaliq Urdu`, `Noto Sans Ol Chiki`) with `font-display: swap` to eliminate tofu boxes (`□`).

## Voice Capabilities Honesty

`GET /api/agent/voice/capabilities?lang=` reports accurate TTS and STT capabilities:
- When a language has authentic audio synthesis support (such as Hindi or English via gTTS), `tts: true` and the engine are reported.
- When server-side TTS lacks coverage for a regional language (such as Odia or Kui), the system reports `tts: false` with `engine: "browser_speech_synthesis_fallback"`. The frontend displays an honest note ("Voice not available for this language, text only") rather than silently speaking a different language.

---

## User Feedback Loop

Learners and educators can suggest translation corrections via the "Report a bad translation" link in the Settings language picker footer. Feedback is sent to `POST /api/feedback/translation` with `{ key, lang, suggestion }` and stored in MongoDB `translation_feedback` for continuous refinement.
